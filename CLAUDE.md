## Collegamento con PiGreco Archivio

Archivio e Posta sono due programmi separati, ognuno funziona da solo. Installati sullo stesso server si parlano sulla rete Docker `pigreco`: la dichiarano **tutti e due** con `name: pigreco` e la chiave `pigreco` (non `external`, mai creata a mano con `docker network create`, che compose poi rifiuta), così funziona in qualsiasi ordine di installazione. L'Archivio pubblica la webmail su `:8081/webmail/` con un proxy verso l'alias fisso **`pigreco-webmail`** e aggiunge a ogni richiesta `X-PiGreco-Archivio: /`: solo le pagine arrivate da lì accendono Archivio/Archivia/Contatti (`$archivioUrl` in `webmail/index.php`, unico punto dove si decide; si accetta solo `/`). `ARCHIVIO_URL` nel `.env` resta per forzarlo sempre. La porta della webmail si chiude alla rete con `WEBMAIL_ASCOLTO=127.0.0.1` (lo propone l'installatore dell'Archivio). Piano completo nel repo dell'Archivio, `servizio/PIANO-ARCHIVIO-POSTA.md`.

## Note tecniche su webmail e copia locale

Riprese il 20/10/2026 dal CLAUDE.md di PiGreco Archivio, quando webmail e posta sono uscite da quel repository. In inglese come l'originale; "Webmail Digitale" e "Posta Digitale" sono i vecchi nomi di webmail e copia locale, e i percorsi docker citati sono quelli che avevano dentro l'Archivio.

### Webmail

**Webmail Digitale** (formerly the separate repo `ddcls/readmail5`, imported with `git subtree` into `webmail/`) is a standalone multi-account IMAP webmail: own users, own DB (`webmail_digitale`), mysqli + Python MIME parser (`email_parser.py`), no framework, UI mostly in `webmail/index.php`. It can still be installed alone (`webmail/deploy.sh`, `config/config.local.php`). UI: three-pane layout (`#pannelloCartelle` folders/account, `#sidebar` list, `#mainContent` reading; on phones one pane at a time via `body.cartelle-aperte` / `body.leggendo`), all colours from CSS variables in `webmail/temi.css`. Colour theme per user (`users.tema`) with an admin default (`impostazioni.tema_predefinito`), migration `webmail/migrations/003_tema.sql` (auto-applied by the container entrypoint); `lib/tema.php` sets `data-tema` on `<html>` server-side, "Aspetto" dialog in `tema.js` → `salva_tema.php`. Keep the existing element ids/functions in `webmail/index.php`: the inline JS relies on them. Phones/tablets (≤960px): `webmail/telefono.js` + `telefono.css` (`PostaTelefono`) add a "current mailbox" bar `#accountCorrente` at the top of `#sidebar` (account + folder, kept up to date by MutationObservers on `#userSelect`/`#emailList`, tap → `toggleCartelle`) and a round ＋ `#fabNuovaEmail` (`composeEmail()`, hidden while reading or with the folder panel open). `apriArchivio()` (archivio.js) goes back to `/telefono.html` in the same tab when localStorage `archivio.versione` = `telefono` (set by the archive's phone page, same origin; "Versione completa" sets `completa`). Multi-select is a separate module `webmail/selezione.js` + `selezione.css` (`SelezioneEmail`): a MutationObserver on `#emailList` adds a checkbox to every `.email-item[data-file]` (both the list and search results, no template changes), bar `#barraSelezione` under `.email-count`, "Sposta in…" dialog (also `.sposta-btn` in the detail toolbar, `spostaAperta()`); actions go to `azioni_email.php` (uids comma-separated, `azione` = sposta/cestino/elimina/letta/non_letta, `elimina` = permanent, only from trash, needs UIDPLUS) → `MailboxService::moveMany/setSeenMany/deleteMany`. On Posta Digitale mailboxes these change only the local copy. Folders: `webmail/cartelle.js` + `cartelle.css` (`CartelleEmail`: "Nuova cartella" under `#altreCartelle`, each folder wrapped in `.cartella-riga` with a ⋯ menu; drag & drop of emails onto `.folder-btn` lives in selezione.js) → `cartelle.php` (azione crea/rinomina/elimina; delete only if empty and without children; the 5 special folders are refused) → `MailboxService::createFolder/renameFolder/deleteFolder` (personal namespace prefix via NAMESPACE; never CLOSE, `closeSelected()` uses UNSELECT or EXAMINE INBOX). Posta Digitale mailboxes (`imap_host` posta/posta_dovecot, `isPostaDigitale()`): only folders created by the webmail (table `cartelle_create`, migration `webmail/migrations/004_cartelle_create.sql`, auto-applied by the entrypoint) can be renamed/deleted (`folderEditable()`, `modificabile` in get_folders.php, plus `solo_locale`), because mbsync would recreate and re-download a renamed provider folder; local-only folders are excluded from mbsync by `postaconf.cartelle_solo_locali()`. Selection is keyed by folder+uid (`data-folder` + `data-file`, search results can mix folders); `esegui()` sends one azioni_email.php request per folder. **Search** (`ricerca.js`, `RicercaEmail`; the "Ricerca Email" dialog's `executeSearch()` delegates to it; it wraps `loadEmails` so any normal reload ends the search) → `cerca_email.php` → `MailboxService::search()` (IMAP SEARCH over the open folder or all selectable ones, max 1000 newest per folder in "tutte", sorted by INTERNALDATE, paged; fields mittente/destinatari/oggetto/corpo + `FLAGGED`). `ImapClient::quote()` falls back to synchronizing literals `{n}` (command() waits for "+") on servers without LITERAL+ (imap.tiscali.it). **Important ⭐** = `\Flagged`: `is_flagged` in list summaries (`data-importante` on rows), azioni `importante`/`non_importante`, `.importante-btn` in the detail. **Drafts** (`bozze.js`, `BozzeEmail`): `send_email.php` with `bozza=1` builds the same message (incl. Bcc via `isMail()`, placeholder recipient `senza-destinatari@bozza.invalid` stripped) and `MailboxService::saveDraft()` APPENDs it to Drafts (\Draft, CRLF), replacing `bozza_uid`; after a real send `bozza_uid` is deleted (`deleteDraft()`). Autosave every 30 s, prompt on close (`closeComposeModal()` → `BozzeEmail.puoChiudere()`), "Modifica bozza" (`.bozza-btn`) reopens it; after each save the attachments are re-based on the new draft through `forward_original_email` = `<account>:draft:<uid>`. `email_parser.py` returns `bcc`. **Filters** (migration `webmail/migrations/005_filtri.sql`, auto-applied; `lib/FiltriService.php`, `filtri.php`, `filtri.js` + `filtri.css`, user menu › Filtri and the funnel `.filtro-btn` in the detail toolbar → form prefilled with the sender): table `filtri` (conditions JSON mittente/destinatari/oggetto/testo/ovunque × contiene/non_contiene, tutte/almeno una; `sposta` NULL/trash/junk/`cartella:<A / B>` created if missing via `MailboxService::folderByPath()`; segna_letta, segna_importante, ferma, ordine, attivo, `applica_esistenti`), global for every mailbox (or one, `account_id`) whoever created them, editable by every webmail user. `filtri_esegui.php` (CLI only, flock) runs every minute from a background loop in `docker/webmail/entrypoint.sh` (setpriv www-data; standalone: cron) → `eseguiGiro()`: per mailbox with filters, UID SEARCH of the conditions on INBOX UIDs above `filtri_stato.ultimo_uid` (first run / new UIDVALIDITY = start from UIDNEXT-1, existing mail only on request), flags first, then the first move wins, `ferma`/a move stops later filters; mailboxes without filters lose their state. Never a permanent delete. Posta Digitale: local copy only; verified that mbsync does not re-download an email moved out of INBOX. **Links in the email body** (webmail `#detailBodyHtml` and the archive's `EmlParser::corpoHtml()`) open in a new tab: `<base target="_blank">` first in the srcdoc, link targets forced/removed, sandbox `allow-popups allow-popups-to-escape-sandbox` (never `allow-scripts`), no referrer — inside the iframe external sites refuse to load ("connessione negata").

**Webmail security rules**: every value that comes from an email (subject, sender, recipients, attachment names, dates, error texts) goes into `innerHTML` only through `escapeHtml`/`escapeHtmlAttr` (in `onclick` strings through `encJs()`); quoted email HTML put into the page (reply, forward, reopened draft) only through `pulisciHtmlEmail()` = DOMPurify (`webmail/vendor/dompurify/`), never regex cleaning; the email body itself stays in the sandboxed iframe. `check_auth.php` refuses non-GET requests from other sites (`richiestaDaAltroSito()` in `lib/session.php`: Sec-Fetch-Site, else Origin vs X-Forwarded-Host/Host — the archive pages calling `/webmail/` are same-origin and pass). Session cookie HttpOnly/SameSite=Lax (Secure under https), new id at login, login throttling from `access_log` (10 failures/15 min per IP, 30 per username), passwords ≥ 8 chars. `lib/`, `config/`, `phpmailer/`, `initializa/`, `migrations/` are denied over HTTP (`docker/webmail/000-default.conf`, `.htaccess`).

### Copia locale delle caselle (ex Posta Digitale)

`posta/` (own `docker-compose.yml`, installable alone; **included** by `docker/docker-compose.yml` with `include: … env_file: .env`, so it starts with the archive and reads `POSTA_*` from `docker/.env`). One image (Debian 12: dovecot-imapd, isync 1.4, python3), three services: `posta` (Dovecot, container `posta_dovecot`, IMAP `POSTA_IMAP_PORT`=143 STARTTLS / `POSTA_IMAPS_PORT`=993; other containers reach it as `posta:143`), `posta-sincronizza` (mbsync per mailbox every `POSTA_INTERVALLO` s, `Sync PullNew PullFlags`, `Expunge None`: never deletes), `posta-gestione` (stdlib-Python web page "Gestione caselle" on `POSTA_GESTIONE_PORT`=8083, own login set with `docker exec -it posta_gestione genera-config imposta-password admin`). Logic in `posta/script/postaconf.py` (account.conf, Dovecot passwd-file, mbsyncrc generation, provider special folders by SPECIAL-USE/name → Sent/Drafts/Junk/Trash, same-name folders → `<name>_gestore`, dots in names → `_`), UI in `gestione.py`. Data in `POSTA_DIR`=/srv/posta (uid 5000 `vmail`, chowned by the entrypoint if Docker created it): `config/account.conf` (provider passwords, `password_locale_hash`), `config/generati/` (caselle.passwd read by Dovecot auth via `extra_groups = vmail`, re-read without restart; mbsyncrc; provider passwords), `config/stato/`, `<indirizzo>/Maildir` (Maildir++, IMAP separator `/`). Default ports assume a fresh server **without** a host Dovecot; on the dev PC `docker/.env` uses 1143/1993. The webmail's default IMAP host (`WEBMAIL_IMAP_HOST`) is `posta`; the webmail is also on the compose `default` network to reach it. Compare provider vs local counts: `posta/script/confronta.sh [indirizzo]`. OAuth2-only providers (Microsoft: hotmail/outlook/live/msn domains, `*.outlook.com`/`office365.com` servers) are refused by `postaconf.richiede_oauth()` (same regexes in the form JS), and the form opens the "Caselle che non si possono aggiungere" dialog. Provider cleanup: `tieni_giorni` per mailbox in account.conf (0 = never delete, the default and the value written by `salva_account`; otherwise ≥ 7; field "Giorni da tenere sul gestore" in the mailbox form of `gestione.py`, which requires the `conferma_pulizia` checkbox when the new value deletes more (0→N or a smaller N) and shows a read-only estimate (`stima_pulizia()`) with "Prova l'accesso al gestore"): after each successful mbsync run `pulizia_nel_ciclo()` → `pulisci_gestore()` deletes from the provider only emails older than N days whose local copy is confirmed (`.mbsyncstate` FarUidValidity = provider UIDVALIDITY, far→near UID pair, file `,U=<uid>` present); `\Deleted` + immediate `UID EXPUNGE` (without UIDPLUS plain EXPUNGE only if every already-`\Deleted` email also has a confirmed copy); never CLOSE; flag removed on failure. mbsyncrc unchanged (no `Delete` in `Sync`, so provider deletions never reach the local copy). Read-only preview: `docker exec -u 5000 posta_sincronizza genera-config pulizia-prova [indirizzo] [giorni]`.

## Copie di backup su dischi USB

Stesso schema di PiGreco Archivio (piano nel suo repo, `servizio/PIANO-BACKUP.md`): ognuno fa il suo backup, sugli **stessi dischi** (partizione ext4 `PIGRECO-<NOME>`), l'Archivio in `pigreco-archivio/`, la Posta in `pigreco-posta/`, ognuno con la sua password (`BACKUP_PASSWORD` nel `.env`, generata da `installa.sh`).

- Servizio `posta-backup` (stessa immagine, `avvia backup` → `posta/script/backup.py`, root): restic 0.19.1 e client MariaDB nell'immagine (`posta/Dockerfile`), `cap_add SYS_ADMIN`, `apparmor:unconfined`, `device_cgroup_rules "b 8:* rmw"`, `/dev` + `/run/udev:ro`, `.env` `:ro`, `hostname: pigreco-posta-backup` (restic toglie solo i lock della stessa macchina). Ogni 30 s: segnale di vita, dischi USB (`lsblk` TRAN=usb, mai quello di `/srv/posta`; `in_uso` = apertura esclusiva rifiutata), richieste, poi `pianifica()` (turno giorni/ora di serie lun–ven 23:00, un'ora dopo l'Archivio; copia saltata; copia al collegamento se l'ultima ha più di 24 h; verifica `restic check --read-data-subset 5%` ogni `verifica_giorni`).
- Copia: `e2fsck -p` (se il disco è aperto anche dall'Archivio o dal desktop si rifiuta e si va avanti), mount solo nel container, snapshot `database` = `mysqldump --databases <quelli di SHOW DATABASES senza mysql/sys/*_schema> --add-drop-database` con `--skip-ssl-verify-server-cert` (il client MariaDB rifiuta il certificato autofirmato di MySQL) via `--stdin-from-command` — **mai `--all-databases`**: lo schema `mysql` scritto dal mysqldump di MariaDB non si ricarica in MySQL 8 (ERROR 3105 su `engine_cost`), e gli utenti di MySQL sono quelli del server su cui si ripristina, snapshot `caselle` = `/srv/posta` senza i file di MySQL (`WEBMAIL_DB_DIR` dentro `POSTA_DIR`) + `.env`, tag comune `esecuzione-<id>`, `forget --prune` con tieni_giorni/settimane/mesi.
- Stato in file JSON in `/srv/posta/config/backup/` (`posta/script/copie.py`, condiviso da pagina e servizio): la pagina (vmail) scrive solo `impostazioni.json` e le richieste in `richieste/`; il servizio scrive `dischi.json`, `stato.json`, `lavori.json`.
- **Un disco già preparato non si formatta mai**: `copie.classifica()` dà `pronto` → "Usa questo disco" (solo `pigreco-posta/`, `restic init` se manca, rifiuta un repository con un'altra password); prima di `wipefs` `contenuto_pigreco()` monta in sola lettura ogni partizione (se `-o ro` è rifiutato perché il disco è aperto altrove: mount + `remount,bind,ro`) e rifiuta se trova `pigreco-archivio/` o `pigreco-posta/`, o se una partizione ext4 non si riesce a guardare. "Non usarlo più" non cancella niente dal disco.
- Pagina **Gestione caselle › 💾 Copie di backup** (`/copie` in `gestione.py`): stato, dischi, "Prepara questo disco…" (`/copie/prepara`, nome + FORMATTA), "Usa questo disco", ultimi lavori, impostazioni. L'immagine va ricostruita dopo ogni modifica degli script (`docker compose build posta`).
- **SMTP dell'amministratore** (Gestione caselle › ⚙️ Impostazioni, `/impostazioni`): `/srv/posta/config/amministratore.json` (600, vmail; password vuota nel modulo = resta quella salvata), invio in `posta/script/avvisi.py` (`smtplib`, cifrari `DEFAULT:!kDHE` per smtp.tiscali.it), "Salva e manda un'email di prova".
- **Avvisi** (`avvisi.avvisi()`): servizio fermo / nessun disco (solo striscia), `vecchia` (> `avviso_giorni`, 3), `fallita`, `pieno` (< 10%), `verifica`, `rotazione` (≥ 2 dischi, collegato da > `rotazione_giorni`, 7). Striscia in cima alle pagine di gestione (nella pagina delle copie dentro il riquadro dello stato); email dal servizio (`avvisi_per_email()`, una al giorno per tipo, 3 tentativi, `config/backup/avvisi_inviati.json`), se `avvisi_email` e SMTP impostato.
- **Foglio di ripristino**: `POST /copie/foglio` con di nuovo la password della pagina → pagina HTML da stampare (una A4) con `BACKUP_PASSWORD` (il servizio `posta-gestione` la riceve solo per questo), dischi, 5 passi, comandi restic.
- **Ripristino completo**: `scripts/ripristina-backup.sh` (host, niente sudo) ferma webmail/posta/sincronizza/gestione/backup, tiene acceso `db`, `docker compose run --rm --no-deps posta-backup python3 backup.py --ripristina` con `/ripristino/esito` (classe `Ripristino`: disco `PIGRECO-*`, password di questo `.env` o chiesta, copie complete, RIPRISTINA, `restic restore <snap>:/srv/posta`, dump nel database, la copia rimasta "in corso" nello stato diventa riuscita, controllo delle Maildir; disco in sola lettura con `remount,bind,ro` e `--no-lock`). Dopo il database caricato (file `database_caricato`) lo script scrive nel `.env` `WEBMAIL_ENCRYPTION_KEY` e `BACKUP_PASSWORD` del vecchio server (le password di MySQL restano quelle nuove), salva `.env.prima-del-ripristino` / `.env.dalla-copia`, rinfresca `/srv/posta/config/pigreco-posta.env` e riavvia `db` più i servizi che erano accesi. Provato in un'installazione separata (`COMPOSE_PROJECT_NAME` diverso, rete rinominata): caselle, account.conf, utenti e account della webmail identici.
- `docker compose exec posta-backup python3 /usr/local/lib/posta/backup.py --dischi` stampa i dischi visti senza scrivere niente; `--avvisi` stampa l'email di avviso che manderebbe.
